# ADR 0006：意图优先、风险自适应的协作流程

- 状态：accepted
- 日期：2026-09-01
- 适用版本：0.2.0

## 背景

首轮真实项目回放显示，阶段图、人工门和中间账本虽然提高了可追踪性，却容易被 Agent 当成每轮必须依次完成的审批流程。用户要求继续某个子问题时，Agent 可能先补规则 profile 或其他可选产物；论文写作阶段则可能把内部编号、草稿状态和审计话语带入最终 TeX。现有行为测试主要验证结构化 envelope，没有验证真实论文的成文清洁和阅读体验。

## 决策

1. 以用户当前意图作为路由优先级。意图可以是理解、探索、文献、建模、实验、写作、修稿、审稿、披露或终检；阶段图只提供推荐路径。
2. 阶段依赖分为两层：`depends_on` 是开始阶段前必须满足的硬依赖；`recommended_after` 是可延后的软建议，不得阻断明确要求的解释、探索、续写或局部修稿。
3. 人工边界分为：
   - `core_decision`：最终采用、定稿或冻结前必须由人确认；确认前 Agent 可以提出候选、暂定分析和可回退草稿；
   - `review_checkpoint`：默认是质量核对点，不把未回复视为确认，也不自动阻断无关工作。
4. 默认运行档位改为 `contest-standard`；需要完整复盘时显式选择 `research-full`，时间紧时选择 `contest-fast`。各档位仍不能删除证据、失败记录、AI 使用事实或核心人工决定。
5. 新增 `modeling-paper-writer` 作为正文写作入口，并取消 `draft` 对结构蓝图/实验审计的硬依赖，改为软建议。它以段落叙事、摘要规范、术语克制和题目特异性为目标；材料不足时标记缺口，明确区分内部追踪层与论文成文层。
6. 最终预检必须运行 `check_manuscript_quality.py`，至少报告草稿/占位符、内部 ID、过程性话语、重复防御性元话语、摘要密度、交叉引用和列表密度风险。该脚本不输出 AI 率、原创度、相似度或获奖预测。

## 保留的硬边界

本决策不允许编造数据、文献、实验或 AI 使用历史，不允许静默改变已确认的模型/假设/结果，不允许将未知变为通过，也不允许 Agent 代替团队签核最终结论和提交版本。

## 后果

- 早期解释、探索和局部写作可以更快推进；
- 计划输出会同时展示硬依赖、软建议、用户意图和协作强度；
- 最终稿需要额外的成文清洁检查，不能只以“编译成功”或结构测试通过为依据；
- 旧版自定义状态若没有 `user_intent`、`collaboration_mode` 或 `review_gates`，仍可通过默认值运行；阶段注册表中新增的 `recommended_after` 和人工门语义需要按 0.2 版本迁移。

## 验证

- registry/schema/profile 交叉验证；
- 明确意图时 ready 阶段排序测试；
- 写作阶段不再硬依赖可选审查透镜的测试；
- 成文质量检查器的正反例；
- 以脱敏真实项目回放作为后续宿主级回归样本，比较用户目标是否被流程覆盖以及最终 TeX 是否仍有流程残留。
