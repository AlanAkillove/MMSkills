# 反同质化设计草案

## 1. 为什么需要单独设计

在 AI 辅助下，数模论文容易同时出现几种趋同：相似的“问题背景—模型建立—算法求解—结果分析—优点展望”章节骨架，相似的模型名堆叠，相似的“创新点”措辞，相似的三点式总结，以及与题目关系不大的通用图表。仅做语言降 AI 味儿无法解决这些问题，因为同质化往往在题意拆解、模型选择和证据组织时已经形成。

反同质化的目标是让论文真实保留这道题的关键结构、团队做过的判断、选择该模型的原因、验证方式和由证据支持的独特观察；表达应保持自然，术语应保持可定义、可复用。

这也与竞赛评阅中的“建模创造性”相容：创造性应表现为对题目结构的有效建模、合理取舍和有证据的观察；改写常见算法名称、堆叠复杂模块或追求文本相似度指标下降，都不能替代真实的题目—证据—决策链。相似度检查与模板化信号审查负责触发人工复核，模型、证据和作者决策仍由相应角色判断。

## 2. 同质化的五个层次

| 层次 | 需要识别的信号 | 更可靠的证据 |
|---|---|---|
| 题目层 | 不解释题面特征，直接套通用变量和目标 | 题面约束、对象关系、边界条件是否进入模型 |
| 建模层 | 常见模型清单式罗列，缺少取舍理由 | 候选模型比较、基线、适配性和放弃理由 |
| 论证层 | 每节都像模板，主张与证据没有独特对应 | Claim–Evidence Matrix 与题目子问题映射 |
| 术语层 | 用新名词包装普通操作，或创新点措辞高度雷同 | 术语账本、定义必要性、跨论文短语聚集仅作线索 |
| 表达层 | 套话、均匀句式、固定三点式、空洞展望 | 具体段落的可删性、句法变化、作者决策和信息密度 |

## 3. 写前差异化账本

在正式写作前建立 `distinctiveness_ledger.md`，至少记录：

```text
题目特有事实：本题不可替换的对象、约束、时间/空间结构
关键观察：团队从题面或数据中得到、并影响建模的观察
候选路径：至少一个基线和若干可行替代方案
选择理由：为什么采用当前模型，为什么不采用其他方案
验证设计：哪些实验专门检验本题的风险或敏感因素
独特证据：哪些结果是本题的主要发现，不是通用宣传语
图表角色：每张图/表回答的具体问题
术语预算：真正需要命名的概念及其复用场景
人类决定：由谁、基于什么证据作出关键选择
```

账本中的“独特”必须与题目和证据相连。若只是把常见算法换成别的算法名，不能算有效差异化。

## 4. 审查算法

1. 从题面提取 3–7 个不可省略的结构特征；
2. 把正文的主要变量、约束、模型、实验和图表映射回这些特征；
3. 找出没有映射的通用段落、模型和“创新点”；
4. 检查每个差异化主张是否有证据和验证；
5. 检查结构是否过度套用模板，但不把常规论文结构本身判为问题；
6. 提出三类动作：补充题目特异性、删除无功能包装、保留合理通用部分；
7. 由人类确认哪些差异化路径值得采用，再交给写作 skill 表达。

## 5. 防止“为了独特而独特”

以下情况应标为风险而不是创新：

- 为了避开常见模型而使用没有数据支持的复杂模型；
- 把简单事实命名为带有“定律、证书、语义、前沿、鲁棒”等高承诺词的新概念；
- 通过不自然的句式、故意加入口语或打乱逻辑来制造人味；
- 只做词语替换，不改变题目—证据—决策链；
- 把一个局部实验结果宣传为一般规律或普适方法；
- 把常见的模型组合说成团队独有的方法论。

## 6. 与其他 skill 的关系

- 在 `modeling-topic-selection` 阶段先比较全场题目，避免不同题目被同一套建模路径覆盖；
- 在 `modeling-problem-familiarization` 阶段从背景地图和文献迁移边界中建立共同的题目语义；
- 在 `modeling-problem-intake` 阶段建立题目特征；
- 在 `modeling-literature-evidence` 的 orientation 模式中记录文献启发与本题差异；
- 在 `modeling-model-architect` 阶段记录模型取舍；
- 在 `modeling-experiment-validator` 阶段验证差异化主张；
- 在 `modeling-paper-architect` 阶段组织独特证据链；
- 在 `modeling-anti-homogenization-auditor` 阶段做跨层审查；
- 在 `modeling-paper-naturalizer` 阶段只做保真表达，不重新发明内容。

## 7. 输出格式草案

```text
Distinctiveness audit
- Paper scope and evidence boundary
- Problem-specific anchors found
- Generic/template-like elements
- Missing links to problem features
- Over-engineering or forced novelty risks
- Evidence-backed distinctiveness that should be preserved
- Recommended structural changes
- Recommended deletions or simplifications
- Human decisions required
- Confidence and unresolved uncertainty
```

审查不能给出“原创度百分比”，也不能据此推断作者是否使用 AI。它只说明哪些地方看起来与题目脱节、哪些地方需要回到团队真实决策。

## 8. 参考实践的借鉴边界

从 `nature-skills` 借鉴：路由器与静态/动态资料分层、按任务轴按需加载、图表先建立结论—证据契约、写作先检查主张/证据/边界、修改后进行一致性扫描。

从 reviewer/humanizer 类开源项目借鉴：证据锚点、严重性分级、独立审查后再综合、保留数字和作者声音、修改日志、反例测试。

不照搬：Nature 期刊的投稿标准、三位互盲审稿人的固定结构、英文句法偏好、期刊版式限制和高影响力期刊的创新性标准。数模竞赛的评价重点、篇幅和交付物不同，必须重新定义。
