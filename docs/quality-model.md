# 数模论文质量模型与问题分类

本模型把历史论文修审中反复出现的问题抽象为可跨项目复用的检查维度。每个问题都应尽可能落到“证据位置—风险—修复动作—人工确认”四元组，而不是只有主观评价。

## 1. 一级维度

| 维度 | 核心问题 | 典型失败表现 |
|---|---|---|
| 选题可决策性 | 是否完整比较候选题，并把题目要求、资源、时间和验证风险交给团队判断 | 只看标题；只分析一题；按流行度/总分/默认推荐选题；没有备选或切换条件 |
| 背景共同理解 | 团队能否用共同语义说明现实对象、关系、过程、测量和子问边界 | Agent 已读懂但成员不懂；空间/时间层级混淆；未完成多轮复述就开始定模 |
| 文献迁移可追溯性 | 每个背景/方法启发是否说明来源、支持范围、不可迁移边界和与本题的差异 | 只看摘要；把“文献用过”写成“本题适合”；后续采用点找不到来源或人工决定 |
| 题意忠实度 | 论文是否正确理解题面、对象、边界和任务 | 把结构关系看反；将示意图视觉印象当作事实；漏掉边界情形 |
| 问题分解 | 子问题、变量、目标和约束是否对应题目 | 章节按算法罗列，没有回答题目；子问题之间断裂 |
| 假设透明度 | 假设是否必要、可解释、可检验且有边界 | 为方便计算默默改题；假设与后文结论不一致 |
| 数据可信度 | 数据来源、口径、清洗和切分是否可复核 | 训练测试泄漏；指标定义漂移；异常值处理未说明 |
| 模型适配性 | 模型复杂度是否由问题和证据需要决定 | 为显得高级使用 LSTM/复杂优化；基线缺失；模型与数据不匹配 |
| 人类可决策性 | 不熟悉模型的用户能否理解用途、关键假设、代价、风险、未知和验证路径 | 只给算法名；黑箱总分；单一“推荐”；把潜在收益写成结果；把用户沉默当确认 |
| 论证闭合度 | 主张是否有直接证据，证据是否支撑主张强度 | 用一张图支撑多层结论；相关性写成因果；结论超出实验范围 |
| 验证充分性 | 是否有基线、误差、敏感性、稳健性或边界测试 | 只展示最好结果；没有空集/极端情形；没有复现实验入口 |
| 术语规范 | 术语是否标准、必要、定义清楚且前后一致 | 给普通事实造新名词；同一概念多称；“exact/certified/law/semantics”等包装词滥用 |
| 阅读体验 | 读者能否快速定位问题、方法、证据和结论 | 段落都很完整但无主线；长句叠加；图表与正文脱节 |
| 图表设计 | 图表是否由读者任务和证据角色驱动，且在目标尺寸下清晰、可解释、可复核 | 选错图型；彩虹色带或只靠颜色；装饰性仪表盘；多面板重复；模板化图形抹平题目特征 |
| 声明负担 | 限定、局限、不确定性和合规说明是否提供必要信息且放在合适位置 | “需要指出的是/不能据此”等自我免责反复出现；有效边界被误删 |
| 表达自然度 | 语言是否像作者在清楚地解释自己的工作 | 模板开头、套话、三段式堆叠、空洞因果、过度对称 |
| 反同质化 | 是否保留题目特征和真实团队判断 | 通用模型清单；创新点换词复述；不同题目写成同一篇论文 |
| 可复现性 | 代码、参数、数据版本和支撑材料是否匹配 | 附录代码不能运行；结果无法复算；文件列表不完整 |
| 规则与隐私 | 提交内容是否符合赛事与格式边界 | 电子版包含不应出现的页面；身份信息泄露；AI 披露字段缺失 |

## 1.1 与竞赛评阅重点的对齐

以 CUMCM 官方评阅材料为一个可配置的参考基线，技能应把以下四个高层问题贯穿到审查中：

- 假设是否合理，并且没有悄然改变题意；
- 建模是否体现题目驱动的创造性，而不是强行换算法或造概念；
- 结果是否正确、可复核，且结论强度没有超出证据；
- 表述是否清晰，使评阅者能沿着问题、模型、证据和结论阅读。

这四项是检查方向，不是自动评分器。相似度筛查、词汇多样性指标和 AI 检测器只能提供待核实线索，不能单独证明抄袭、AI 生成、作者身份或论文质量。其他赛事应由规则 profile 覆盖或调整本节适用范围。

## 2. 高频跨项目反模式

### 2.1 高级感替代了信息

将“终点接触”“阈值降低”“有限审计”“稳健时间宽度”等普通描述包装成新概念，但没有带来新的变量、定理、指标或决策价值。处理方式：先问该术语是否在全文至少承担两次以上明确功能；若不能，用普通、标准且可读的表达替代。

### 2.2 还没有共同理解就开始建模

题面、背景和文献已经被 Agent 快速总结，但团队尚未确认对象关系、数据产生过程、子问语义和来源边界，随后直接列模型、写代码或包装创新。处理方式：回到题目熟悉阶段，按轮次记录说明、团队复述、证据核对和纠正；结构性分歧关闭前不解锁正式模型冻结/采用，但可以在用户明确要求时展示标为暂定的候选解释。

### 2.3 结构完整但论证不连

论文有摘要、模型、算法、实验和结论，却像模块拼装。处理方式：建立 `claim_evidence_matrix`，要求每节说明“这一节为哪条主张提供什么证据”。

### 2.4 语言很顺但事实漂移

润色时偷偷改变数值、条件、因果强度、引用范围、符号或作者立场。处理方式：修改前后对照、数字/公式/引用锁定、变更日志和人工抽查。

### 2.5 以 AI 检测器代替文本判断

检测器的误报、跨语言偏差和可操纵性使其不能作为作者归因或违规判定。处理方式：只报告可观察的模板化信号，并要求以证据和作者确认作最终判断。

### 2.6 先写漂亮句子，再补模型依据

导致问题定义、假设和验证不足，后续只能反复重写。处理方式：先完成问题地图、假设账本、模型注册和证据矩阵，再进入自然化。

### 2.7 用“反同质化”掩盖过度设计

为了与常见论文区分而强行增加复杂算法、新概念或不必要图表。处理方式：任何差异化设计都必须有题目依据、技术功能和验证结果；不能解释其必要性的内容优先删除。

### 2.8 防御性声明替代有效边界

论文需要报告适用范围、误差、不确定性、失败、局限和合规信息；问题在于同一免责句式反复出现，却没有新增条件、证据或范围。处理方式：逐句分类，保留有效边界，将其并入结果/讨论的直接表达；只删除没有独立信息的元话语，并把功能不明的句子交给人工确认。

## 3. 严重性分级

- `P0`：事实/数学/数据/规则错误，或会导致错误提交；必须阻断后续阶段。
- `P1`：主要主张缺证据、模型不适配、验证不足或严重阅读障碍；修复后再冻结。
- `P2`：术语漂移、段落逻辑、图表说明、引用位置等重要但可局部修复的问题。
- `P3`：句式、标点、局部冗余和排版微调；不得为了修 P3 引入 P0/P1 漂移。

## 4. 证据和置信度

每个审查结论标记：

- `direct`：可直接定位到题面、正文、公式、数据、代码、图表或规则条文；
- `inferred`：由多个直接证据推断，必须标明推断链；
- `unknown`：材料不足，不能确定；
- `external`：依赖外部规范/文献，必须给出处和适用范围。

任何“AI 味儿”“模板化”判断默认最多是 `inferred`，不应升级为作者来源结论。

## 5. 成功标准

高质量结果不等于问题数量多或句子更华丽，而应同时满足：

1. 核心事实、数学、数据和规则没有被改写错；
2. 读者能复原关键决策和证据链；
3. 术语数量受控，定义与使用一致；
4. 语言自然、直接、符合作者和学科语域；
5. 重要结论可验证，未知和局限被诚实保留；
6. 题目特征和团队真实判断没有被通用模板抹平；
7. 论文、代码、数据、图表、支撑材料和披露记录互相一致。
