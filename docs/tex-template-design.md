# 数学建模论文 TeX 模板设计与调研记录

版本：`0.1`
调研日期：2026-08-31
范围：提供的既有 TeX 论文实例、用户提供的 CUMCM 格式规范 PDF、CUMCM/COMAP/MathorCup/中国研究生数学建模竞赛公开文件，以及可复用的开源 TeX 工程实践。

## 1. 先分清三类东西

本项目把以下内容分开维护：

1. **通用写作骨架**：章节、公式、图表、引用、附录和复现入口，服务于任何数模论文；
2. **赛事格式适配**：摘要/summary 首页、目录、页眉页脚、页数、匿名、附录/代码、AI 声明和文件命名，由目标赛事和年份 profile 决定；
3. **交付检查**：从干净目录编译、渲染真实 PDF、扫描 warning/元数据/匿名信息和支撑材料一致性。

如果把三者混在一份 `.tex` 中，就会出现“模板看起来规范但套错赛事”的问题：CUMCM 电子版通常不放目录，COMAP 当前 instructions 要求目录和控制号页眉，研究生数模可能要求使用不可删除的官方封皮，MathorCup 的公开历史规则又有自己的摘要/目录顺序。

## 2. 从既有 TeX 实例提炼的可迁移部分

提供的实例中值得保留的工程做法有：

- 使用 XeLaTeX 处理中文和数学混排；
- 将页面边距、行距、首行缩进、浮动体、图注、表格列和代码环境集中配置；
- 常用 `amsmath`、`booktabs`、`tabularx`、`graphicx`、`listings`、`natbib` 等宏包，服务于公式、图表、代码和数字引用；
- 使用 `\label`/`\ref`、相对图片路径和 `latexmkrc`，使正文、图表、参考文献和构建入口可以复核；
- 内容顺序覆盖摘要、问题重述、问题分析、假设、符号、分问题模型、验证、局限、结论、参考文献和附录；
- 将支撑材料清单、复现命令和必要源代码交接到附录或支撑包。

以下内容没有进入通用模板：

- 实例的具体题名、对象、数据规模、参数符号、参考文献 key、图名、结果和代码路径；
- 依赖本地字体文件的固定字体设置；
- 带有赛事承诺书、编号页和专用页的 CUMCM 文档类；
- 指向某个项目输出目录的深层相对路径；
- 固定的 AI 使用声明文字和具体工具名称；
- 为某一篇论文服务的固定“五问”、固定图表数量和固定“模型特点”段落。

## 3. 赛事规范对照

| 赛事/材料 | 已核验的排版或提交信号 | 对通用模板的设计影响 |
|---|---|---|
| CUMCM 2026 格式规范 | A4、四边至少 2.5 cm；纸质版有承诺书/编号页/摘要页顺序；电子论文首页为摘要页，不放承诺书和编号页；正文不超过 30 页、不要目录、附录页数不限；电子 PDF/Word 不超过 20 MB；支撑包另行提交并在附录列清单；正文/附录/支撑材料匿名；字号字体行距颜色未统一指定 | 通用模板默认摘要先行、页脚页码、无目录/页眉、四边 2.5 cm；官方模板和赛区要求优先；正文和附录分开统计；不把字体和“美观”写成 CUMCM 硬性规则 |
| CUMCM 2026 AI 试行规定 | 参考文献**前**二选一声明；使用 AI 时另交 `AI工具使用详情.pdf`（工具、用途/环节、主要提示方式与过程、采纳/修改/核验）；核心由队伍主导；**不要求**参考文献列 AI 或正文标注 | AI 声明做成显式开关；事件记录和 profile 未完成时不插入最终声明；详情 PDF 由披露 skill 生成；禁止按 2025 细则往 `.bib` 或正文塞 AI 著录 |
| COMAP MCM/ICM 2027 instructions | 英文、可读字号至少 12 pt；Summary Sheet 首页；目录、正文、参考文献/附录按当届说明组织；每页顶部要有控制号和页码；匿名；PDF 和页数/文件大小受限；提供官方 LaTeX Summary Sheet | 开启目录/页眉必须是 profile 决策；英文学术表达和中文 CUMCM 分开适配；总页数定义不能由模板猜测 |
| MathorCup 第十三届公开格式页 | 题目、摘要、关键词第一页；目录第二页；正文开始编号；无页眉；中文；正文约 30 页、附录不限；引用和程序/支撑材料有专门要求 | 作为历史对照，不写成 2026/未来赛事规则；保留目录和页眉独立开关 |

## 4. 设计决策

### 4.1 使用中性 `ctexart` 骨架

仓库提供 `templates/tex/main.tex`，默认使用 `ctexart`、XeLaTeX、A4 和四边 2.5 cm。它只依赖常用宏包，不捆绑来源/许可证/版本不明的 `cumcmthesis.cls`、Logo 或字体。用户确实需要第三方文档类时，由 Agent 记录来源、许可、版本和修改情况后再使用。

### 4.2 把易冲突的格式做成开关

模板提供五个源稿开关：

```tex
\mmIncludeContentsfalse
\mmIncludeAIStatementfalse
\mmIncludeCodeAppendixfalse
\mmShowHeaderfalse
\mmIncludeBibliographyfalse
```

开关只解决机械排版，不替代 profile：

- 目录开关不能证明目录在目标赛事中被允许；
- 页眉开关只提供控制号和页码占位，不自动生成真实队号；
- 代码附录开关不能解决页数和源代码完整性；
- AI 声明开关不能生成未知的工具、版本、用途或核验事实。

### 4.3 默认优先阅读体验

模板骨架保留“问题—方法—证据—结论”的读者路径，但不固定论文必须有多少问题或多少节。每个子问题段落都要求说明任务、模型、求解、验证和范围；图表先在正文找到读者任务再插入；长推导和代码只有在规则和证据价值都支持时才进入附录。

这与“套一个漂亮版式”不同：字号、颜色、阴影和标题装饰不能代替变量定义、单位、图注、主张边界和结果说明。模板也不鼓励通过轮换同义词或生造高级术语制造“专业感”。

### 4.4 许可证和可复现性优先

开源模板可借鉴目录组织、构建脚本、配置开关和文档方式，但不能把用户未授权的 `.cls/.sty/.bst`、字体、Logo 或论文内容直接复制到本仓库。中文参考文献可以在确认发行版和许可证后使用 GB/T 7714 风格；模板默认保留可移植的 `plainnat`，由 profile 决定是否切换。

## 5. 实现内容

- `templates/tex/main.tex`：通用单文件入口；
- `templates/tex/references.bib`：空引用库，防止模板制造假文献；
- `templates/tex/latexmkrc`：XeLaTeX 构建配置；
- `templates/tex/tex-format-profile.example.yaml`：赛事适配记录；
- `templates/tex/tex_build_manifest.example.yaml`：构建输入输出和人工确认记录；
- `templates/tex/tex_layout_audit.example.md`：页面抽查和问题记录；
- `skills/modeling-tex-paper-production/`：TeX 生产、迁移、编译、渲染和版式审计 skill；
- `skills/modeling-tex-paper-production/scripts/check_tex_template.py`：检查入口、开关、引用入口、绝对路径和真实项目标记；
- `tests/test_modeling_tex_paper_production_contract.py`：技能、模板、脚本和文档契约测试。

## 6. 尚未自动化的事项

以下事项保留在人工或赛事 profile 阶段：

- 当届赛区对字号、封面、装订、命名和页数计算的附加要求；
- 官方模板、专用字体和图片资源的许可与版本；
- PDF 中正文页数与附录页数的自动分段计数；
- PDF 元数据/图片 EXIF/代码路径的完整匿名扫描；
- 视觉审查中“读者是否能在目标尺寸下读懂图表”的最终判断；
- AI 使用详情中无法从历史会话恢复的工具版本、提示词、输出和人工决定。

这些未知项要写入构建清单或版式审计报告，不以编译成功替代确认。
