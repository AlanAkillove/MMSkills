# 角色、交接与人工确认门

## 1. 推荐角色

### 人类角色：Research Chair

负责最终确定题意、研究问题、关键假设、模型取舍、数据口径、实验结论、创新性表述和提交/披露内容。该角色可以由队长或团队共同承担，但必须可追溯。

### Agent 角色

| 角色 | 能做什么 | 不能替人决定什么 |
|---|---|---|
| Research Scout | 搜索、整理和核验公开资料 | 哪些资料最终用于论文 |
| Problem Interpreter | 拆解题面、列出歧义和边界 | 题意的最终解释 |
| Model Architect | 提出基线和候选模型，提供通俗用途、分项适配评估、代价、风险、未知和验证路径 | 最终模型、关键假设和采用/放弃决定 |
| Experiment Engineer | 写脚本、运行实验、整理指标和图表 | 结果是否足以支持主张 |
| Figure Designer | 根据读者任务、证据角色和题目特征选图、编排面板、制作源文件和渲染件 | 展示范围、删留结果、颜色语义、关键标注和最终图版 |
| Adversarial Reviewer | 寻找数学、数据、论证、合规和同质化风险 | 论文是否可以提交 |
| Paper Editor | 组织结构、术语、读者路径和语言 | 改变事实、结论、作者立场 |
| Compliance Clerk | 抽取规则、核对格式、整理 AI 事件 | 是否对未知事实作补充或“合理猜测” |

Agent 角色可以由同一模型在不同阶段承担，但每次交接都要说明角色边界和使用的状态文件。

## 2. 交接产物

每次阶段交接至少包含：

- `stage` 和 `status`；
- 输入材料范围、版本/hash 和读取边界；
- 已确认事实；
- 未解决问题；
- 主要主张及证据位置；
- 人类已确认/待确认的决策；
- 下一阶段允许做的事情和禁止做的事情。

## 3. 必须阻断的情况

- 题面关键对象或边界存在未确认歧义；
- 核心模型、数据处理或结论只有 AI 建议，没有人类决定/验证；
- 用户只看到算法名称、总分或单一推荐，尚未通过本题对象复述理解候选的用途、关键假设和主要风险；
- 主张没有直接或可解释的证据；
- 规则版本不明、规则冲突未处理或提交材料包含未知身份信息；
- AI 使用详情无法从记录恢复，却准备以确定语气生成；
- 为了反同质化而引入没有题目依据的复杂内容；
- 自然化修改改变数字、公式、引用、条件、因果强度或结论边界。

## 4. 可自动化的工作

- 文件索引、分页读取、文本提取、hash 和版本记录；
- 术语/数字/单位/交叉引用的机械扫描；
- 图表的源文件导出、目标尺寸渲染和视觉自检；
- 论文图表引用、支撑材料清单、PDF 页数/大小和身份信息扫描；
- 将已确认事件渲染为披露报告；
- 对候选问题去重、排序和生成修复清单。

自动化结果仍需保留原始证据位置，不得把“扫描未发现”写成“绝对不存在”。

