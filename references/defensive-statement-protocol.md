# 论文防御性声明处理协议

## 目的

本协议处理论文正文中反复出现、主要用于预先自我辩解而没有增加研究信息的声明。目标是降低阅读负担、恢复直接表达，不是删除谨慎性，也不是让文字迎合任何检测器。

“防御性声明”不等于所有限定语、局限、不确定性或合规说明。只有当表述主要承担自我保护/流程辩解功能，且没有新增对象、条件、证据、范围或决策信息时，才可考虑删除或合并。

## 识别信号

以下只是定位线索，不是固定禁用词表；必须结合段落功能和相邻证据判断。

| 信号 | 可观察表现 | 常见风险 |
|---|---|---|
| 元话语前置 | 连续使用“需要指出的是”“值得注意的是”“需要强调的是”等句首，但后文没有新增研究信息 | 延迟进入对象、动作和结果 |
| 自我免责重复 | 多次说明“本文不……”“不能据此……”“这并不意味着……”，每次都没有新的范围或证据 | 读者反复遇到同一层面的自我辩护 |
| 结论逐句设防 | 每个结果句后都追加泛化的免责声明，局限段又重复一遍 | 打断结果—证据—边界的阅读路径 |
| 合规/过程混入正文 | 把工具、流程或责任划分的解释写成与研究结论无关的长段落 | 稀释核心论证；也可能掩盖真正的合规披露位置 |
| 有效边界的误报 | 简短限定实际说明样本范围、误差、不确定性、伦理/隐私或规则要求 | 若误删会扩大主张或造成不合规 |

可把前三类作为 `defensive_statement_cluster` 线索；第四类通常交给结构/披露技能；第五类是必须防止的误报。

## 功能分类

逐句标记声明的实际功能，而不要只看句式：

- `scope_boundary`：限定样本、时间、空间、参数或外推范围；
- `uncertainty`：报告误差、置信度、随机性或未知来源；
- `limitation`：报告方法、数据、实验或解释的限制；
- `ethics_compliance`：伦理、隐私、许可、赛事规则或必要披露；
- `process_defense`：解释工具、流程或作者责任，但不改变论文主张；
- `meta_disclaimer`：泛化的自我免责，没有可核验的新信息。

## 处理判据

| 功能 | 默认动作 | 可接受的动作 | 不得做的事 |
|---|---|---|---|
| `scope_boundary` / `uncertainty` / `limitation` | 保留 | 与对应结果或讨论合并，压缩重复措辞 | 不得删除后扩大结论范围或确定性 |
| `ethics_compliance` | 保留在规则要求的位置 | 按赛事/项目规范移到 AI 披露、方法或声明部分 | 不得为“更自然”省略合规信息 |
| `process_defense` | 先判断是否应移出正文 | 缩成一句并放入合适的过程/披露材料 | 不得把未知事实写成已发生的人工决定 |
| `meta_disclaimer` | 可删除或合并 | 改为直接陈述对象、条件、结果和边界 | 不得用同义词继续堆叠免责句 |

## 固定工作流

1. 锁定版本、段落功能、主张—证据关系和术语账本；
2. 标出候选声明及其相邻结果句，记录是否提供了新的条件、证据或范围；
3. 将候选句按功能分类，并检查同一功能是否在本节或全文重复；
4. 对有效边界优先采用“结果 + 条件/范围 + 影响”的直接结构；
5. 只有在删除不改变主张强度、适用范围、合规状态和作者立场时，才建议 `remove`；
6. 功能不明、涉及赛事/伦理/隐私、或可能改变证据边界时，输出 `human_review`，不自动处理；
7. 修订后回查摘要、结果、讨论、结论和 AI 使用详情，确认边界没有被重复删掉或互相矛盾。

## 记录格式

```yaml
statement_id: DEF-0001
location: null
surface_text: null
function: scope_boundary | uncertainty | limitation | ethics_compliance | process_defense | meta_disclaimer | unknown
new_information: null
repetition_scope: local | section | global | none | unknown
action: retain | merge | remove | human_review
reason: null
protected_fact_or_boundary: null
human_status: unreviewed | needs-human-confirmation | human-confirmed | rejected | unknown
decision_id: null
```

`remove` 只适用于没有独立信息的元话语或重复句；不能仅因句子含有“不”“不能”“仅”就删除。若同一有效局限在多个位置出现，保留最能帮助读者理解的位置，其他位置改为简短交叉指向或合并。
