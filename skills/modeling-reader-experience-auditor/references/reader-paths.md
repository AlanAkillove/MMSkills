# 三条读者路径与信息负担

## 快速评阅者

### 目标

在有限时间内回答：这篇论文解决什么问题？每个子问题怎么回答？最重要的模型和结果是什么？结果适用到哪里？有哪些局限？

### 检查序列

```text
标题/摘要 -> 问题回答 -> 关键图表 -> 结论/局限 -> 需要回查的模型与证据
```

常见摩擦：摘要只有背景没有结果；每一题的结果埋在算法细节中；结论没有数值/条件/图表入口；标题和小节标题无法提供信息。

## 技术复核者

### 目标

在不询问作者的情况下尽量复原：对象、变量、单位、假设、公式/算法、参数/数据、验证、结果和代码入口。

### 检查序列

```text
题面对象/任务 -> 变量/单位 -> 假设 -> 模型/算法 -> 参数/数据
  -> 推导/运行 -> 验证/图表 -> 主张/结论
```

常见摩擦：符号先用后定义；同一符号换名；参数无来源；公式与代码/文字不一致；图表不说明对应主张；关键步骤只在截图中出现。

## 非本专业读者

### 目标

知道研究对象、决策量、为什么关注该指标、图表看什么和结果覆盖到哪里，不要求读懂全部推导。

### 检查序列

```text
现实对象 -> 建模问题 -> 必要术语/量的直觉 -> 图表/结果 -> 条件与局限
```

常见摩擦：背景过长但不说明问题；缩写/术语没有最低解释；颜色和图例无语义；“显著改善/有效”没有说明比较对象和范围。

## 信息负担的可观察代理

记录额外查找、回读、歧义、视觉阻断和注意力负担的具体位置。不要把实际回读次数臆测成精确数字；无法实测时用 `unknown`，用“需要跨三节回查定义”描述可观察路径。

## 修复优先级

1. 让读者能找到题目回答、关键证据和结论边界；
2. 在首次使用前给出必要定义、单位、图表语义和模型入口；
3. 合并重复，移动已有信息，删除空话；
4. 最后处理标点、断行和审美偏好。

“补充解释”必须来自已有题面、账本、代码、图表或作者确认，不能用 Agent 新增机制和数字。
