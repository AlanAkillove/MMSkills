# 题目特异性覆盖矩阵

## 六列回查

对每个题目锚点依次回查：

| 锚点 | 问题分析 | 变量/约束 | 模型取舍 | 实验/图表 | 主张/结论/局限 |
|---|---|---|---|---|---|
| A-01 | present/partial/absent/unknown |  |  |  |  |

关键词出现不等于覆盖。`present` 需要回答“它改变了哪一个决策或证据”；只在背景中提到的锚点通常最多为 `partial`。

## 五层问题清单

### 题目层

对象、关系、时间/空间结构、容量/资源限制、评价目标、子问题和边界是否改变了建模路径？

### 建模层

是否有可解释基线？最终模型和被放弃模型是否有题目驱动的取舍？复杂度是否超过数据和验证能力？

### 证据层

是否有专门验证题目特殊风险的推导/实验？图表是否回答本题的具体问题？失败和局限是否被删掉？

### 术语/贡献层

“创新/原创/统一/鲁棒/最优”等词是否有定义和相称证据？普通操作是否被新名词包装？

### 表达/图表层

摘要、章节、段落、图表和结论是否围绕题目子任务组织？固定三点式、算法清单、空洞背景和宏大展望是否占用了证据位置？

## 修复动作分类

- `restore_anchor`：把已有的题目事实和团队决策放回恰当段落；
- `map_evidence`：把已存在的实验/图表/代码入口与锚点和主张连起来；
- `simplify`：删除无功能包装、重复和不必要模块；
- `constrain_claim`：把过强的创新/普适/最优表述限缩到已验证范围；
- `verify`：要求重跑、补基线、补边界或检查版本；
- `human_decision`：把模型、实验、术语和结论选择交给团队。
