# 假设影响与验证指南

该指南帮助选择“验证什么”，不是要求每个项目执行全部方法。先看假设影响的对象，再选择最小有效检查。

## 影响分层

1. **题意/结构影响**：改变对象、关系、时间范围、可行域或子问题输出。通常是 P0，先人工确认。
2. **数据影响**：改变样本代表性、缺失处理、测量误差、切分或外部数据适用性。需要数据审计、替代处理或敏感性。
3. **模型影响**：改变方程、分布、独立性、参数识别、目标或算法。需要基线/替代模型、残差/诊断、极限情形或证明边界。
4. **结论影响**：改变比较、因果、最优、鲁棒、普适或外推强度。必须调整验证设计或降级措辞。
5. **表达/计算影响**：只影响近似、离散化、绘图或实现细节。仍要核对数值、单位、代码和图表，但不应被夸大为模型创新。

同一假设可能跨多个层级；逐项记录，不以一个“影响较小”概括。

## 可选验证动作

| 前提类型 | 可能的最小检查 | 不能由该检查推出 |
|---|---|---|
| 单位/量纲 | 量纲表、单位换算、守恒/数量级 | 真实机制或因果关系 |
| 边界/结构 | 零值、极值、退化、空集、不可行和方向反转 | 全域普适性 |
| 近似/简化 | 与保留项、基线或替代模型比较；参数扰动 | 一定“更准确” |
| 分布/独立性 | 图表、残差、分组/时间外检查、稳健标准误或替代方案 | 仅凭可视化证明假设成立 |
| 缺失/异常 | 缺失模式、不同处理策略、上下界敏感性 | 缺失机制可被确定 |
| 因果/机制 | 仅在设计支持时做对照、时间顺序或机制核验 | 相关性图表自动变成因果证据 |
| 代码/离散化 | 小规模手算、精确特例、单元测试、收敛/步长检查 | 代码运行成功证明模型合理 |
| 外推/稳健 | 留出、时间外、压力测试、参数范围扫描 | 超出测试域的可靠性 |

## 结果写法

记录“检查做了什么、观察到什么、支持到什么范围、没有支持什么”。例如：

> 在参数 `r` 的 `[a,b]` 扰动范围内，排名顺序未改变；该结果只支持该范围和当前数据，不足以声称模型对所有场景鲁棒。

如果检查未运行、结果矛盾或样本太少，保留 `not-run`/`inconclusive`/`contradicts`，并把结论限缩；不要补造通过理由。

## 反事实问题

对每条高影响假设至少问一个“如果放宽/反转会发生什么”：

- 可行解是否消失或增加？
- 目标/排序/最优方案是否改变？
- 参数是否不可识别？
- 哪一张图、哪一条主张或哪个结论需要重写？
- 当前实验是否真的覆盖了这个变化？

这些问题用于规划验证和限定结论，不要求 Agent 自行决定答案。
