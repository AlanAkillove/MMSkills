# 论文图表视觉系统

视觉系统的目的不是让所有图长得一样，而是让读者在不同图之间快速复用“谁是基线、谁是方案、哪里是边界、误差表示什么”的阅读规则。保留论文的题目特征和证据差异；统一基础语法，避免统一成模板。

## 尺寸优先

1. 先确定目标页面、栏宽、图注位置、是否跨栏和目标纸张；
2. 再确定图的物理宽高比、字体层级、线宽和标记大小；
3. 最后设置像素尺寸/DPI，导出并在实际嵌入尺寸下检查。

不要把“分辨率高”当作“可读”。小图中比 DPI 更先失效的是字号、线宽、标记、图例和中文字体。

## 最小视觉语法

### 层级

- 主焦点：读者必须先看到的比较、趋势、边界或流程节点；
- 支撑信息：基线、背景范围、次要系列、误差或参考线；
- 解释信息：直接标签、单位、图注和必要注释；
- 不保留无功能的边框、阴影、渐变、图标和重复标题。

### 颜色

先写颜色语义，再选具体色值：

```text
neutral      背景、未选中对象、参考范围
baseline     基线/现状/标准方案
candidate    候选方案或实验条件
focus        需要读者关注的结果
boundary     约束、风险、不可行或警示
```

定量色带按数据方向选择顺序型、发散型或循环型；分类色只表示类别，不暗示大小、好坏或顺序。关键对象同时使用线型、标记、位置、明度、纹理或直接标签，确保颜色失效时仍可读。

建议：控制类别色数量；测试常见色觉差异和灰度打印；不要在同一语义上让红/绿、蓝/橙、深/浅同时承担互相冲突的含义；不要把 `jet` 或彩虹色带当成“更丰富”。

### 线、点和标注

- 实线/虚线/点划线只表示预先定义的语义，例如观测/预测、基线/候选或边界/内部；
- 标记形状用于补充分组，不能仅凭大小暗示重要性；
- 误差线和区间必须在图注定义；
- 直接标签优先于读者在远处图例和曲线之间来回寻找；
- 注释应贴近证据，避免文字墙、箭头交叉和遮挡数据；
- 当一张图需要大量注释才能说明重点时，优先重画数据关系或拆分面板。

## 中文与公式排版

- 统一中文字体、英文字体、数学字体和粗细；确认目标环境真实安装，而非只在本机回退；
- 术语、变量、单位、上下标、希腊字母和方案编号与术语账本、公式和正文完全一致；
- 坐标轴写“量名（单位）”或项目确定的等价格式，不把单位藏在图注或图例中；
- 避免竖排长句、过度旋转标签和中英混排造成的错位；
- 若字体无法嵌入或渲染环境不稳定，记录字体、回退方案和人工确认，不把乱码交付给正文。

## 多面板故事

每个面板至少有一个独立角色：

```text
A 总体/问题场景
B 主要比较或机制
C 边界、误差、残差或敏感性
D 适用范围、失败案例或补充验证（确有必要时）
```

面板之间只共享已经定义的尺度和语义；不能为了视觉整齐强行共享不适合的坐标。面板标题应帮助读者完成任务，而不是只写“(a)(b)(c)”。所有面板共同支撑的结论要在图注或正文中说明证据范围。

## 题目特异性与反模板

检查以下问题：

- 这张图是否能换一个题目而不做任何改动？若能，回到题目锚点和证据角色；
- 颜色、箭头、圆角框和“系统架构”是否只是包装，还是表示实际变量、约束、流程和数据流？
- 是否用统一配色掩盖不同实验的量纲、基线和不确定性？
- 是否把普通结果改名为“机制、引擎、闭环、矩阵、域”等高级词，却没有新增计算或读者信息？

反同质化不等于故意使用罕见颜色、复杂布局或不规则字体。最有效的差异通常来自题面对象、边界条件、实验比较和真实取舍。
