# 验证准备度

## 候选进入实验前

每个候选至少明确：

1. 要检验的题目风险或主张；
2. 与哪个基线/候选比较；
3. 数据、参数、时间/实体切分和随机设置；
4. 评价指标、边界/可行性检查和不确定性呈现；
5. 成功、失败或无法判断的判据；
6. 代码入口、输出和版本 hash；
7. 实验后如何影响采用/放弃/限缩结论。

没有这些字段可以保留为 `candidate`，但不能写“验证模型有效”。

验证前的“潜在收益”只能写成待检验假设，例如“若能处理容量约束，可能比贪心基线少一个局部决策限制”；实验完成前不能写成“效果更好”。用户简报应把这条假设、比较基线和失败判据一起呈现。

## 不同任务的最低验证

- 预测：时间/实体一致的留出、基线、误差分布和反复试验控制；
- 优化/决策：可行性、约束满足、基线比较、参数/边界敏感性和实际解释；
- 仿真：参数来源、边界、重复/随机设置、输出不确定性和与观测/基线对照；
- 估计/解释：识别条件、误差/区间、替代假设和结果覆盖范围；
- 组合/规则模型：极端情形、不可行情形、复杂度和小规模可手算/穷举核对。

这些是检查方向，不是保证某种模型正确的固定清单。
