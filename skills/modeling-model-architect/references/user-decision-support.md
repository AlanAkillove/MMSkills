# 候选模型用户决策支持协议

本协议把复杂的模型注册翻译成用户可以比较和追问的说明，同时保留数学、数据和验证细节。它降低认知负担，不降低人类决策权。

不使用总分、信心百分比或单一推荐替代分项证据；“验证优先级”也不等于“应当采用”。

## 三层交付

### 1. 一句话层

用当前题目对象完成句子：

```text
在本题中，{模型} 用 {输入/已知量} 计算或预测 {输出/决策量}，主要处理 {题目目标/约束}。
```

不能只写“这是一个先进的优化模型”或“适合复杂数据”。如果输入、输出或题目映射不清，写 `unknown` 并停留在候选阶段。

### 2. 比较层

逐候选回答：

```text
为什么列入候选：
相比可解释基线多处理什么：
额外付出什么（数据、假设、时间、实现和解释）：
关键风险/最可能失败的位置：
当前已有证据：
仍未知什么：
下一步最小验证是什么：
```

“多处理什么”必须对应题目结构或可验证证据，不得把模块数量、模型名称或文献声望当作收益。“额外付出”必须具体到数据、参数、调试、复现或写作承载能力。

### 3. 决策层

在比较层之后只给出下一步选项：

- `先验证 A`：列出为什么 A 的关键不确定性最值得先检验；
- `先补材料`：列出缺失的题意、数据、假设或资源；
- `并行小规模验证`：仅在成本和授权允许、且实验能区分候选时使用；
- `暂不决定`：保留候选，不写入 adopted 或论文主张。

可以给出“验证优先级”，不能给出脱离证据的“最终推荐”“胜率”或“选它就对”。如果用户要求 Agent 直接决定，返回候选比较和人工确认门，不替代签核。

## 解释难度控制

- 首次出现的算法名同时给“标准名称 + 一句话作用 + 本题对象映射”；
- 数学表达先解释变量、输入输出和约束，再展示公式；
- 用基线作对照：“基线先做什么；候选新增什么；因此增加什么成本”；
- 用本题小例子帮助理解时，明确“示意例子”，不把示例数值当实际结果；
- 把事实、基于资料的推断、待验证预期和未知分栏；
- 一次最多提出少量关键问题，允许用户请求换一种解释、术语解释或反例；
- 不要求用户掌握算法内部全部细节后才拥有否决权。用户只需先理解用途、关键假设、主要代价/风险和待验证点即可作阶段性决定。

## 理解校验而非形式同意

不要只问“看懂了吗”或让用户点击默认按钮。对每个候选提出少量、可直接回答的复述问题：

1. 在本题中，它把什么输入变成什么输出？
2. 哪个关键假设如果不成立，结果最可能如何失效？
3. 相比基线，它增加了哪一项主要数据、实现、计算或解释成本？

用户可以用自己的话回答，也可以指出仍不明白的术语。Agent 只检查回答是否回到了当前题目对象和已记录材料，不评价用户能力，也不把回答解释为接受模型；答不清时把状态记为 `incomplete` 或 `needs-reexplanation`，换一种解释后再询问。没有这一步不能把候选写成 `human-confirmed`，但用户始终可以直接否决候选。

## 最小人工确认门

在模型状态从 `candidate` 变为 `adopted` 前，记录以下四项：

```text
用户是否知道模型解决什么：yes | no | unclear
用户是否知道一个关键假设：yes | no | unclear
用户是否知道一个主要代价或失败风险：yes | no | unclear
用户选择：adopt | reject | continue-validation | pause | undecided
decision_id / decision_owner / decided_at:
understanding_check: not-asked | incomplete | answered | unknown
comprehension_status: not_presented | explained | needs-reexplanation | user-confirmed | unknown
```

前三项有 `no/unclear` 时，先解释或继续保持候选；最后一项必须由人明确选择。未回复、没有回复、只点击默认项、只说“你看着办”或只看到一个分数，都不能写成 `human-confirmed`。即使 `understanding_check: answered`，也不能替代人的 `adopt/reject/continue-validation/pause/undecided` 选择。

## 推荐的卡片结构

```text
模型名（标准术语）：
一句话用途：
输入 → 输出：
为什么列入候选：
相比基线新增什么：
分项评估：适配度 / 假设负担 / 数据准备度 / 可解释性 /
          计算实现成本 / 验证准备度 / 潜在收益
关键假设：
可能失败：
已有证据与来源：
仍未知：
下一步验证：
人类确认问题：
状态：candidate | adopted | rejected | ...
```

卡片必须能独立阅读，但完整技术字段仍回到 `model_registry.md` 和相关证据。简明说明不得删掉限制、失败路径和不确定状态。
