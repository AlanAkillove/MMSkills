# 自然化修稿的推荐工作流

本文件是按需读取的详细协议，不是每轮必须执行的 SOP。用户只要改一节或诊断几段时，直接进入该范围。数字、公式、引用和结论边界仍须锁定。

## 修订模式

- `diagnose-only`：只报告模板化信号和缺口，不改原文。
- `signal-targeted`（终稿精修默认）：每个改动必须对应一个 `signal_id`；未命中的句子保持原样。
- `minimal-edit`：只做能明确改善信息传递的最小修改，可用于方法/结果段。
- `paragraph-rebuild`：仅当用户明确要求整段重写，或出现结构层阅读问题时，保留证据和段落功能后重排。
- `section-revision`：跨段处理重复和信息顺序，逐块保存差异。
- `diff-audit`：只核对已有修订是否改变保护内容。

`signal-targeted` 下，revision_log 没有 `signal_id` 的 diff 视为越权润色，应撤回。

## 需要完整留痕时的顺序

1. 固定论文版本和 SHA-256 hash，建立保护清单（数字、公式、引用、标签、否定、量词、因果词）。
2. 按需读取问题地图、假设账本、主张—证据矩阵、术语账本和图表注册；缺少则标未读取。
3. 先诊断段落功能，再做结构级最小修复，再做句式自然化，最后回归术语与证据。
4. 防御性声明按共享协议区分边界/局限/元话语；功能不明时 `human_review`，不自动删。
5. 机械核对保护 token，再语义抽查主语、范围、条件和主张强度。无法解释的差异视为阻断。

## 需要落盘时的最低交付

`revised_text.md`、`revision_log.md`、`preservation_report.md`。内部 ID 和暂定状态不得写进论文正文。
