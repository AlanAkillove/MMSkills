# 论文与支撑材料一致性

## 清单对照

建立双向表：

| 论文/附录声称 | 支撑文件/路径 | 版本/hash | 是否可读/可运行 | 影响 |
|---|---|---|---|---|
|  |  |  |  |  |

检查：附录文件列表与包内文件、代码入口与命令、数据/配置与论文样本、图表与实验输出、模型/参数/单位与代码、AI 详情和规则要求是否互相对应。额外文件也要解释，不能只查“缺少”。

## CUMCM profile 的可选规则

若目标 profile 明确要求支撑材料，按 profile 检查论文/支撑分离、附录列表、可运行源程序、自主查阅数据、大篇幅中间图表、压缩格式/大小、匿名信息和 AI 详情文件；若目标赛事没有这些要求，写 `not_stated`，不自动提出违规。

## 复现状态

- `metadata_only`：只核对清单/hash；
- `static_checked`：检查入口、依赖、语法或配置，未实际运行；
- `authorized_run_success`：在记录的安全环境中成功运行并核对输出；
- `authorized_run_failed`：授权运行但失败，保留日志和限制；
- `blocked/unknown`：权限、文件或安全条件不足。

静态文件存在不等于复现成功；README 的声明不等于实际内容。
