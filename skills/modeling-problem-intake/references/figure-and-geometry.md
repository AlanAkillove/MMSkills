# 图示、几何与结构关系读取协议

题面中的图可能是精确约束、示意图、流程图、网络图、坐标图或仅用于帮助理解的插图。解析时先确认图的类型和图注，再记录内容；不要默认“画出来的”都具有数学约束。

## 三层记录

1. **可见事实（visual）**：标签、箭头、节点、线段、编号、图例、明确的坐标轴、文字标注、线条存在和相对位置。连接或包含关系只有在端点/边界清晰且没有与正文/图注冲突时才可作为可见观察；否则记为 `unknown`。
2. **题面语义（direct）**：正文或图注明确说出的平行、垂直、相切、等长、比例、方向、连通、顺序、不可穿越等条件。
3. **解释推断（inferred）**：根据前两层提出的几何/结构含义。推断必须附替代解释和确认问题。

## 禁止从图形外观直接推出

- 示意图比例、角度、长度、曲率或面积比例；
- 没有标注的平行、垂直、共线、相切、对称、等距或连通；
- 线条交叉就一定相交，线条靠近就一定相邻；
- 颜色、粗细、阴影、透视或排版位置代表变量、权重、优先级或因果方向；
- 图中未标明的节点编号、箭头方向或边界延伸；
- OCR 猜出的符号、下标、负号、单位或小数点。

## 关系核对表

相对位置、线段存在和标签只能作为 `visual` 观察；连接或包含关系需要清晰端点/边界以及图注或正文支持。两条线靠近、交叉不清或被遮挡时，不得把它们升级为连接关系。

对每个可能影响模型的关系，至少问：

| 问题 | 记录方式 |
|---|---|
| 主体和客体是谁？ | 使用题面名称或中性 ID，不用图上位置代替 |
| 关系方向是什么？ | 记录箭头/文字依据；无方向时写未知 |
| 条件是否文字明确？ | `direct` / `visual` / `inferred` / `unknown` |
| 是否存在反向或替代解释？ | 列出会改变模型的最小分支 |
| 哪个边界会受影响？ | 记录进入歧义队列的原因 |
| 如何由人确认？ | 指定题面段落、原图高清版或队伍决定 |

## 图像质量不足

若图像分辨率、裁剪、遮挡、颜色或字体导致关系无法确认：

1. 记录图片路径/页码和具体不可读区域；
2. 只保留能确认的标签和关系；
3. 请求高清原图或人工说明；
4. 在确认前禁止将该区域用于最终变量、约束或结论。

不要通过常见几何题型、相邻页文字或外部答案“修复”缺失图像。

## 典型反例

- 图画得像直角，不等于存在直角条件；
- 两条线在低分辨率图片中似乎相交，不等于节点相连；
- 流程图中的上下位置不等于时间先后，除非箭头或文字明确；
- 网络图中的边粗细不等于容量或权重，除非图例或题面定义；
- 坐标轴未标单位时，不得把刻度间隔当成真实长度。
