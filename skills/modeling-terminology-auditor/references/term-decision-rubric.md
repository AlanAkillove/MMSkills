# 术语保留与回退判据

该判据用于帮助人工决定，不是自动给术语打分。先确认概念是否真实存在，再决定名称。

## 保留项目术语的必要条件

至少同时满足：

1. 有与其他概念不同的明确指称；
2. 在当前题目/模型中有可操作定义或计算方式；
3. 承担变量、指标、流程、结构或决策上的技术功能；
4. 有题面、数据、公式、实验或团队决定作为依据；
5. 在多个必要位置复用，或作为后续推导/图表/代码接口的稳定标签；
6. 删除或改成普通表达会丢失信息，而不只是降低“高级感”。

不满足时不要靠“听起来专业”补足理由。

## 高承诺词核对

| 词类 | 需要的最低桥接 | 常见保守回退 |
|---|---|---|
| 定律/定理/规律 | 明确数学命题、条件、推导或跨场景证据 | 关系、观察到的趋势、在本数据中的现象 |
| 证书/认证/保证 | 可复核的证书构造、验证条件或正式保证 | 检查结果、验证记录、判据 |
| 语义/机制 | 具体语义定义、机制变量或因果证据 | 含义、解释、相关因素 |
| 审计/诊断 | 明确审查对象、规则、输出和可复核过程 | 检查、分析、核对 |
| 鲁棒/稳定 | 扰动域、边界条件和结果变化证据 | 在已测试范围内变化较小/排序未变 |
| 精确/最优/普适 | 误差/最优性/适用域的严格边界 | 近似、当前候选中最好、在本题场景下 |
| 智能/前沿/范式 | 不能只靠宣传性语气；需要技术定义和比较证据 | 自动化、所用方法、当前方案 |

## 同义变体决策

- 若对象、尺度、时间范围或统计量不同，保留不同术语并补定义；
- 若只是中文/英文、全称/缩写或代码接口差异，登记为 alias 并统一首次定义；
- 若含义完全相同，选择一个 canonical term，其余标为 alias/deprecated；
- 若不能确认是否同一概念，标为 conflict/unknown，不能自动合并或拆分。
