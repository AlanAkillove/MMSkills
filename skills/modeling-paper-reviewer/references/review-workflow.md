# 审稿工作流与独立性

## 一次完整预审

```text
固定版本/规则/授权范围
  -> 快速读故事线并记录初始可复核问题
  -> 题意与材料 manifest 回查
  -> question / model / data_experiment / claim_evidence / reader_expression / compliance 独立审查
  -> 各透镜冻结 findings
  -> 合并同一底层问题，保留多个证据锚点
  -> 排序 P0/P1/P2/P3，生成验收标准
  -> 人工确认模型、假设、数据、结论和规则事项
  -> 输出报告、JSONL、续接 checkpoint
```

## 读者路径

### 快速评阅

只读标题、摘要、问题回答、关键图表和结论，记录不能回答的问题；再回查正文，不因第一印象直接定性。

### 技术复核

沿变量→假设→模型→算法→数据→实验→结论路径复原，优先检查支撑主要结论的最短证据链。

### 交付/合规

检查目标规则、匿名信息、论文与支撑材料的对应关系、AI 披露和文件状态。没有适用规则 profile 时，输出待核验清单而不是合规判断。

## 独立审查与综合

- 一个 Agent 可以按多个透镜自审，但不得伪装成多个真实评委；
- 用户明确要求多角色或多人协作时，透镜/角色之间不共享未冻结的判断；
- 每个角色先只记录 findings，冻结后才综合；综合时按底层问题去重，不把同一问题复制六遍；
- 不同意见保留冲突和证据，不用投票制造“共识”；
- 任何外部材料比较都要记录授权范围和来源，不能在竞赛保密窗口内开展未授权比较。

## 有效意见模板

```text
[REV-0001 | P1 | model | blocking=true]
原文锚点：……
可观察事实：……
审稿判断：……
替代解释/不确定性：……
为什么重要：……
最小修复方向：补证据 / 限缩主张 / 对齐代码 / 请求人工决定
验收标准：……
```

避免使用“整体不严谨”“AI 味很重”“模型太简单”等无法验收的总评；若要给总评，必须由具体 findings 支撑。
