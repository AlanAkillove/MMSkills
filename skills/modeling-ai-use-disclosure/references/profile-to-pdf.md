# 规则 profile 到 PDF 的映射

PDF 是 profile 的渲染结果，不是规则的替代品。生成前要把赛事、年份、来源、版本/生效日期和 profile 哈希写入 `disclosure_manifest.json`；profile 不明确时只能生成草稿。

## 建议的 PDF 结构

按 profile 的 `required_fields` 和 `detail_fields` 决定具体栏位，通常包括：

1. 赛事/年份、文档状态、记录范围和完整性；
2. AI 工具名称、开发者、版本或模型（未知须显式标出）；
3. 使用阶段、目的、输入范围和输出摘要；
4. 采用状态、人工修改、人工核验和最终产物关联；
5. 对实质内容的影响：语言、资料支撑、代码/计算、模型、数据、实验、结果或结论；
6. 代表性事件及其证据等级；
7. 未知项、冲突项、部分历史、隐私限制；
8. 人工确认人、日期、决定 ID、签核范围。

对于 CUMCM 2026，应把官方规则中的工具/版本/模型、用途与阶段、提示与过程、采纳/修改/核验等详情映射到上述字段；语言润色的例外也要按照该 profile 的原文解释，不得扩展成“所有语言润色都无需说明”。规则快照见 `../../../references/rules/cumcm-2026.yaml`，其来源和生效信息见 `../../../docs/research/source-register.md`。

## 草稿与 final

`draft` 文档必须在首页或页眉明显显示“草稿 / 待人工确认”，并显示未决字段和记录完整性。`final` 至少要求：

- profile 已验证且未过期、无规则冲突；
- 授权范围明确，历史完整性和隐私处理有记录；
- 必填事件字段不为未知；
- 核心内容事件的采用、人工修改和核验可追溯；
- 作者确认 `confirmation.status=confirmed`，且有确认人、日期和决定 ID；
- 生成后文本校验与渲染视觉检查均通过。

如果比赛允许“AI 未使用”，也必须由作者确认；不能从没有检索到会话推断为零使用。

## PDF 质量门

用 `scripts/build_disclosure_pdf.py` 生成，用 `scripts/validate_disclosure.py` 做机器校验，再按 PDF skill 渲染页面检查：

- 中文字体可见，标题、表格和状态标识不乱码；
- 长字段自动换行、不裁切、不挤出页面；
- 表格跨页仍能看出列头和事件 ID；
- 规则来源、范围和未知项没有被页尾截断；
- 没有密钥、隐藏提示、未授权身份、模板占位符或未解释的空白栏；
- PDF 文本层与输入 JSON 一致，`render_status` 真实反映是否完成视觉检查。

生成失败、字体不可用或视觉未检查时，报告 `P2/P1`，不要把未完成文件命名成最终交付件。
