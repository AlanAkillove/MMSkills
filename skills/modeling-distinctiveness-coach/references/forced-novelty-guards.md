# 强行创新护栏

## 风险判据

| 观察到的动作 | 需要追问 | 若不能回答 |
|---|---|---|
| 为避开常见算法加入复杂模块 | 题目/数据哪个结构必须它？基线差多少？能验证吗？ | 标为 `forced_novelty_risk`，回到可解释基线 |
| 给普通操作起高承诺名字 | 是否有新量、判据、操作和定义？是否多次承担功能？ | 回退标准术语，交术语账本 |
| 把一次局部实验称“方法创新” | 是否有对照、范围、失败边界和可复现证据？ | 限缩为当前实验观察 |
| 删除失败方案/负结果 | 删除是否改变读者对取舍和可靠性的判断？ | 保留真实失败或写明缺失 |
| 用固定三点式/模型清单讲故事 | 每一点是否对应题目子任务和证据？ | 合并或改为题目驱动路径 |
| 用文本差异替代建模差异 | 哪个对象、约束、验证或决策真的不同？ | 不输出原创度/相似度结论 |

## 高风险包装词

`定律`、`定理`、`证书`、`机制`、`语义`、`前沿`、`鲁棒`、`最优`、`智能`、`统一框架`、`原创算法` 等词不是禁词，但必须有相称的数学证明、实验设计、定义或规则依据。普通回归、加权、排序、参数调优和可视化优先使用标准名称。

## 安全替代

把“本文提出一种全新的……”拆成可核对的陈述：

```text
在 [题目锚点] 下，团队选择 [路径/处理]，原因是 [数据/约束/验证证据]。
与 [基线/替代] 相比，在 [当前条件] 下观察到 [结果]；该观察不外推到 [未验证范围]。
```

这不是固定套话，而是检查差异化是否有对象、动作、条件、证据和边界的结构。
