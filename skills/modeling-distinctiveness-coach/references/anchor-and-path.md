# 题目锚点与建模路径

## 锚点提取表

| anchor_id | 题面/图示原文锚点 | 对象/关系/约束 | 若删除会改变什么 | 进入变量/模型/实验的位置 | 状态 |
|---|---|---|---|---|---|
| A-01 |  |  |  |  | observed/unknown |

锚点是题目中不可随意替换的结构，不是“这个问题很重要”之类的背景句。优先记录量词、时间窗口、容量、空间关系、资源限制、评价目标和子问题之间的依赖。

## 路径比较表

| path_id | 路径/模型 | 题目适配 | 数据要求 | 可解释性 | 计算/实现成本 | 验证方式 | 失败边界 | 采用/放弃理由 | 人工状态 |
|---|---|---|---|---|---|---|---|---|---|
| PATH-BASE | 最小可解释基线 |  |  |  |  |  |  |  |  |

至少保留一个能运行或可计算的基线；其他候选是否采用由团队决定。路径比较不是为了找到“最复杂”的方案，而是解释为什么当前方案能以可接受成本回答题目。

## 四联链

```text
题目锚点
  -> 团队建模决策（变量/约束/假设/数据处理）
  -> 针对性验证（推导/对照/敏感性/边界/图表）
  -> 限定范围的发现或决策建议
```

任一箭头无法提供证据时，记为断链；不能用“创新”“先进”“有效”填空。

## 题目特异性覆盖检查

对每个 A-ID 回答：

- 在正文的哪个段落/式子/图表中出现？
- 它是否改变了模型或验证，而不是只出现在背景？
- 它是否对应至少一条主张和证据？
- 如果没有，应该补充、删除还是明确说明暂未处理？
