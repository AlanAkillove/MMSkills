# 数学建模论文写作

## 目标与边界

本技能负责“把已有工作写成论文”。它关注论证顺序、段落功能、摘要规范、术语克制、读者阅读路径和作者语气，不把论文写成阶段报告、审计清单或固定模板。它可以根据当前材料写初稿、续写指定问题、重组章节或补写摘要/结论。

题意解释、关键假设、模型取舍、数据处理、实验结果和最终结论仍由人类确认。材料尚未完全确认时，Agent 可以继续写候选/暂定表达，但必须把不确定性留在内部交接记录或明确的暂定标记中；最终提交稿不得残留这些过程标记。

## 何时触发

- 用户要求开始写数模论文、续写某个问题、根据已有分析搭建正文或重写摘要/结论；
- 已有草稿需要从“流程报告/清单”改成连贯论文；
- 用户要求保留真实项目特点，减少套话、分点堆叠和生造高级术语。

如果用户只要求审稿、术语核验、图表事实核对或排版，调用相应专项 skill；不要因为开始写作就自动启动全套审计流程。

## 推荐工作方式（不是必须的固定顺序）

1. 先确认本轮目标和范围：整篇、摘要、某一子问题、某一节，还是续接上一轮草稿。用户明确要求继续时，优先推进该范围；不因可选账本或审查报告缺失而无故停住。
2. 读取完成本轮所需的最小材料：题目/问题地图、已采用的假设和模型、数据与实验结果、图表、引用和已有正文。缺失内容写成待补缺口，不凭空补全。
3. 先建立本节的论证线：本题对象或矛盾是什么，做了什么决定，为什么这样做，证据是什么，结论能覆盖到哪里。章节标题和顺序随题目与证据变化，不套固定“五问”或“三段式”。
4. 以段落为主要表达单位。列表只用于真正并列的任务、假设、参数或结果；如果列表是在替代因果/转折/解释，应改写成连续段落。每段尽量让对象、动作、条件、结果和证据可追踪。
5. 摘要通常在主体结果稳定后写：交代对象和任务、各子问题的主要方法、关键结果、结论范围与必要限制。按实际问题数和信息密度分段，不强行一段，也不把“创新点”写在证据之前。
6. 完成后做一次“成文清洁”：删除草稿状态、审计编号、账本编号、待填占位符、对用户/Agent 的说明和重复防御性声明；保留真正影响结论范围的限制、未知和合规信息，但把它们放在合适的讨论位置。默认 TeX 只负责排版，正文章节由题目和证据决定。

## 文字判断准则

- 普通术语优先：只有能缩短后文、明确区分对象或有可靠来源的术语才保留；不要把“框架、范式、机制、赋能、协同、闭环”等包装词当作贡献。
- 具体先于抽象：优先写本题的对象、变量、操作和结果，少用脱离题目的“本文提出一种……体系/路径/范式”。
- 结果先于评价：先给出数值、比较、图表或条件，再说明其意义；“显著、有效、稳健、优越”等词必须有对应证据。
- 限定要有功能：范围、条件和局限应保护主张边界，不把每句话都写成自我辩护。
- 不用同义词轮换制造自然感；术语和变量按项目账本统一，句式变化服务于逻辑，不服务于“像人”。

## 交付与人工边界

可以交付：用户指定范围的论文正文、摘要/结论、章节重组建议，以及一份不进入正文的 `writing_notes`，列出未确认事实、证据缺口和建议复核点。

正文中不得出现内部 finding/decision/assumption ID、流程状态、提示词、审计说明或未经用户要求的安装/工具说明。若必须保留暂定内容，先给出“暂定稿”并在正文外列明范围；不要把暂定结果伪装成最终定论。

## 停止条件

- 题面、数字、公式、引用、代码结果或结论之间存在实质冲突：暂停相关句子的定稿，指出证据位置；
- 缺少支撑某个关键结果的材料：降低表述强度或留出待补位置，不编造证据；
- 用户要求改变核心模型、假设、数据处理或结论：转交相应决策/审计 skill，请用户确认后再改写；
- 只是缺少可选的流程文档、格式偏好或某个 review checkpoint：可以继续写作，并把影响说明为非阻断风险。

## 与其他技能的衔接

`modeling-paper-architect` 提供论证与章节建议，但不是本技能的硬性模板；`modeling-paper-reviewer`、`modeling-ai-pattern-reviewer`、`modeling-reader-experience-auditor` 和 `modeling-paper-naturalizer` 可在成稿后按风险选择。最终 TeX 清洁化和 PDF 检查由 `modeling-tex-paper-production` 与 `modeling-final-preflight` 负责。
