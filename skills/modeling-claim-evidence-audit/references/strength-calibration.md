# 主张强度校准表

下表是风险提示，不是机械替换词表。先看主张的完整对象和条件，再决定证据是否匹配。

| 高风险主张 | 至少需要检查 | 证据不足时的保守方向 |
|---|---|---|
| “证明/必然/定理” | 形式定义、条件、完整推导或可复核证明；计算结果不能代替证明 | “在给定条件下计算表明/得到”或标为未验证 |
| “最优/全局最优” | 明确可行域、目标、约束、算法停止/最优性保证和比较范围 | “在测试候选/当前算法中目标值最好” |
| “导致/影响/机制” | 设计支持的因果识别、时间顺序、对照或机制证据 | “与……相关/伴随变化/在本实验中观察到” |
| “准确/效果好” | 预先定义指标、数据划分、基线、误差/不确定性和公平比较 | 写出指标与数据范围，不用空泛“准确” |
| “显著” | 合适检验、假设、阈值、效应量、不确定性和多重比较处理（若适用） | “观察到差异”并报告数值/范围 |
| “鲁棒/稳定” | 参数/数据/场景扰动范围、边界/压力测试和结果变化 | 限定为已测试扰动范围 |
| “普适/可推广/适用于所有” | 目标域定义、外部/时间外验证或明确理论边界 | 限定为当前数据、题设场景或测试域 |
| “创新/首次/独特” | 与相关方法/题目约束的可核验比较，且主张不能只是换名词 | 描述具体题目驱动设计，不做无证据优先性宣称 |
| “提高/优于” | 同一任务、数据、指标、预算和比较协议；说明不确定性 | “在当前设置下高于某基线” |

## 不要混淆的证据层级

1. 形式推导/证明：说明数学对象在明确条件下的性质；
2. 可复现实验/计算：说明代码、数据和参数下的结果；
3. 经验观察：说明当前样本或场景中看到的现象；
4. 外部引用/背景：说明别人如何定义或发现，是否适用于当前问题需另核对；
5. 团队判断/规划：说明选择和待做验证，不是已完成证据。

跨层级上推必须有额外桥接论证；不能从第 2/3 层直接跳到普适因果结论。
